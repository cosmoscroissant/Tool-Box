# Analyzer
## pseudo-C
pseudo_C_analyzer.py is for organizing pseudo-C generated by IDA. It will look for a file named 0 (entry point), and start from there. It goes through each function and generate 4 files according to "pseudo_C_analyzer_lib.txt", which provides functions and non-function filters.
- "all_function.txt" for all functions mentioned in the provided codebase
- "missing_functions.txt" for later checkouts
- "organized_code.txt" for a clean, complete code output
- "flow_chart.txt" for complete call graph to view function relationships

f.y.i. pseudo_C_analyzer.py will delete these 4 files before creating new ones.

### How-To
`python3 pseudo_C_analyzer.py <path>`

## Low Level Control Flow Intermediate Representation
ida_ir_pattern_analyzer.py is a CFG (Control Flow Graph), DFG (Data Flow Graph) and instruction level patterns combination.

f.y.i. The IR file I use IDA to generate is named "microcode", it's actually low level control flow IR.

### How-To
`python3 ida_ir_pattern_analyzer.py <path>`

### Feature Analysis
#### All Feature
Extracting 27 numerical measurements, these numbers become the input for comparison.

- Graph Structure Features (0-7)
  - num_blocks: total basic blocks
  - num_edges: control flow connections
  - avg_block_size: mean instructions per block
  - max_block_size: largest block size
  - cyclomatic_complexity: decision points (edges - nodes + 2)
    - [Cyclomatic complexity wikipedia](https://en.wikipedia.org/wiki/Cyclomatic_complexity)
    - "For a single program (or subroutine or method), P always equals 1; a simpler formula for a single subroutine is M = E - N + 2"
  - depth: longest path through CFG
  - avg_branching_factor: average outbound edges per node
  - loop_count: back edges in CFG
- Register & Call Features (8-9)
  - register_diversity: unique registers used/defined
  - call_diversity: ratio of unique function calls
- Instruction Type Ratios (10-18)
  - memory_ops_ratio: proportion of load/store ops
  - arithmetic_ops_ratio: math operations
  - control_ops_ratio: jumps, calls, returns
  - floating_point_ops_ratio: FP operations
  - condition_ops_ratio: conditional sets
  - stack_ops_ratio: push/pop operations
  - data_ops_ratio: data movement operations
  - flag_ops_ratio: flag manipulation operations
  - special_ops_ratio: privileged operations
- Data Flow Features (19-23)
  - def_use_chain_length: average distance from register definition to use
  - register_reuse_ratio: how often registers are redefined
  - memory_dependency_depth: longest chain of dependent memory ops
  - live_range_average: how long registers stay "alive"
  - data_flow_complexity: unique def-use paths
- Abstract Operation Features (24-26)
  - abstract_alu_ratio: ALU operations in abstracted instruction stream
  - abstract_mem_ratio: memory operations in abstracted instruction stream
  - abstract_ctrl_ratio: control operations in abstracted instruction stream

#### Goal
Extract features for comparison.

#### Code

### CFG
#### Code
Each basic block becomes a node, and edges are created based on the outbounds field parsed from IDA's microcode. The CFG enables calculating metrics like cyclomatic complexity, depth, branching factor, and loop detection.

```
def build_cfg(self, blocks: List[BasicBlock]) -> nx.DiGraph:
    G = nx.DiGraph()
    block_ids = {b.block_id for b in blocks}
    
    for block in blocks:
        G.add_node(block.block_id, size=len(block.instructions))
        for outbound in block.outbounds:
            if outbound in block_ids:
                G.add_edge(block.block_id, outbound)
    return G
```

#### Feature
- control flow complexity metrics from compiled binary
  - algorithmic complexity (simple linear vs complex nested logic)
- branching density and loop structures as recovered by IDA
  - conditional branching patterns (sparse vs dense decision trees)
- cyclomatic complexity and graph depth
  - loop structure characteristics (flat vs deeply nested iterations)

#### Goal
- identify consistent complexity levels across known samples
- detect algorithmic approach similarities
- serve as consistency check: "Does this binary's control flow match the attributed source's typical patterns?"

### DFG
#### Code
For each register defined in a block, BFS (breadth first search) traverses the CFG to find blocks where that register is used. It tracks the distance (block hops) between definition and use. This captures def-use chains and variable liveness.

```
    def bfs_def_use_search(self, start_block_id: int, reg: str, block_map: Dict[int, BasicBlock], max_depth: float, max_uses: float, max_iterations: float) -> List[Tuple[int, int]]:
        distances = []
        visited = set()
        queue = deque([(start_block_id, 0)]) 
        iterations = 0
        
        while queue and len(distances) < max_uses:
            iterations += 1
            if iterations > max_iterations:
                print(f"    Warning: Block {start_block_id}, reg {reg} - BFS exceeded {int(max_iterations)} iterations")
                break
            
            curr_id, dist = queue.popleft()
            if dist > max_depth or curr_id in visited:
                continue
            visited.add(curr_id)
            
            curr_block = block_map.get(curr_id)
            if not curr_block:
                continue
            
            if curr_id != start_block_id and reg in curr_block.use_registers:
                distances.append((curr_id, dist))
                if len(distances) >= max_uses:
                    break
            
            for next_id in curr_block.outbounds:
                if next_id not in visited:
                    queue.append((next_id, dist + 1))
        
        return distances
```

#### Feature
- register usage patterns in compiled binary
  - register allocation and reuse patterns
- data dependencies as IDA reconstructs them
  - data dependency complexity
- def-use chains and live range characteristics
  - memory vs register operation balance

#### Goal
- show consistency in compilation settings (optimization levels)
- identify data handling characteristics across samples
- detect unusual patterns: "This binary's register usage deviates from expected profile"
